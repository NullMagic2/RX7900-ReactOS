Additional hardware adaptation, src/display/dcn32_otg.cpp:
https://raw.githubusercontent.com/torvalds/linux/v6.12/drivers/gpu/drm/amd/include/asic_reg/dcn/dcn_3_2_0_offset.h
SHA-256 1e693846c3c95226fb7daaa7b80822edb240da6513b331d8622656f56f5a425e
Exact OTG0..3 register DWORD offsets and BASE_IDX=2, bank stride=0x80.
Uses the dcn_3_2_0_sh_mask.h hash below for field widths and shifts, requested/
current master-enable, clock/reset/busy, interlace/stereo/division, update locks
and pending timing state. Both generated headers carry AMD's 2022 MIT notice
preserved below. Segment2 base is supplied only by verified DMU3.2.0 IP discovery
and checked against the actual owned MMIO aperture; no absolute physical or
host-specific register base is hardcoded.

Read-only HPD adaptation, src/display/dcn32_hpd.cpp: the same pinned DCN3.2
offset and mask headers above supply HPD0..4_DC_HPD_INT_STATUS in segment2
(first DWORD offset 0x1f14, stride 8) and DC_HPD_SENSE bit 1. The native
adapter accepts only a validated DMU3.2.0 segment2 and an owned BAR5 mapping,
plus an external proof of exact HPD pin routing and lease serialization. This
does not initialize HPD, AUX/DDC, PHY, link clocks or DCN output.

Reuses optc1_program_timing's ten horizontal/vertical total, sync, blank,
polarity and vtotal-min/max register writes, but only for a proven disabled OTG.
Existing prepare_optc_timing supplies all values. Unlike the full Linux function,
this component does not program global synchronization/VTG, clocks, planes,
pixel format/division, interlace, link training or OTG enable. Those remain
required before real physical output. Each read-modify-write preserves unrelated
bits and is confirmed by masked readback; all fields are rechecked after the
batch. Caller explicitly holds actual ASIC/firmware ownership, stable clocks,
exclusive register serialization and quiesced VTG/pipe/link. Guard reads before
every write enforce disabled/current-disabled, clocks on and no reset/busy,
unsupported division/interlace/stereo, dynamic-vtotal selection or hardware lock.
Any potentially applied write followed by error/mismatch permanently quarantines
the programmer instance; no optimistic retry or unproven rollback occurs.
disabled_fields_verified proves only inactive register fields, never a working
physical stream. No native caller enables this component yet because verified
IP discovery and complete display initialization are absent.
