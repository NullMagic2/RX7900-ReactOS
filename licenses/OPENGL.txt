Module: rx7900.provenance.opengl
Purpose: Record OpenGL contract references and implementation limits.
Created: 2026-10-21

The fixed-function frontend is original C++ implementation. It does not copy
Mesa, Khronos, ReactOS or Sonic runtime source. Public API enumerants and required
mathematical behavior are compatibility facts. No third-party implementation
permission notice is therefore asserted for fixed_function.hpp/.cpp. The GFX11
packet construction in gfx11.hpp/.cpp adapts AMD PM4 definitions and RadeonSI
draw/address emission and carries the permission notices preserved below.
Existing project SDMA,
display and memory modules retain their own upstream permission notices.

Mesa contains separate API frontends, graphics drivers, shader compilation and
platform integration. Its software and layered backends are not Navi31 hardware
acceleration. No Mesa API frontend or shader compiler is compiled into this project;
the bounded PM4 adaptation described below is separate from those runtime stacks.

Khronos normative OpenGL 1.1 specification:
https://registry.khronos.org/OpenGL/specs/gl/glspec11.pdf
Contracts: column-major postmultiplied matrices; homogeneous clip coordinates;
inverse-transposed eye normals; positional/directional lighting; compatibility
quad and quad-strip vertex order; flat-shaded final provoking vertex; display
list commands evaluated under the call-time matrices.

  SHA256 858ba95ea3c9af4ded1f4100e59b6e8e57024f3efef56304dbd48106e8f2f6f7
Frontend supports the relevant matrix/normal/material/light operations, retained
display lists, triangles/quads/quad strips, viewport, depth/culling state and flat
or smooth vertex colors. Color/depth clear operations preserve default and explicit
clamped clear values and require a real attachment backend. The tests observe
transformed triangles and clear requests and never render
or claim GPU completion. They include an independently authored annular geometry
test with the gears retained topology, not copied gears application source.

Frontend limits: no native WGL/ICD exports, GL version strings, pixels, depth buffer,
shader compiler, complete GFX11 pipeline/raster backend, clipping, presentation, display
list allocation through glGenLists or native contexts. The command API is an
internal bounded frontend, not a conformant public OpenGL implementation. It has
one default light and material, no texture/specular/fog/selection/evaluator stack.
Retained lists have explicit command-arena capacity, nesting and total expanded
command budgets, preventing exponential acyclic references from running forever.
Application pointer validation and native ABI translation remain OS boundaries.
A graphics backend must consume clip-space triangles, clip all six planes,
apply perspective division and interpolation, honor depth/culling/viewport,
retain owned GPU buffers through fences, submit GFX11 work and present to the
correct drawable. An absent backend fails explicitly.

WGL ICD and GL 1.1 context, 2026-10-23 (src/opengl/gl_api.hpp, gl_pipeline.*,
gl_clip.*, gl_raster.*, gl_context.*, gl_shader_gfx11.*, src/opengl/icd/*):
original C++ implementation. gl_api.hpp enumerant values and the transform,
lighting, clipping and per-fragment behaviour are OpenGL 1.1 compatibility facts
from the Khronos specification above; no Mesa, Khronos or ReactOS implementation
source is copied. icd_table.hpp reproduces the GLDISPATCHTABLE / GLCLTPROCTABLE /
PFN_SETPROCTABLE / DHGLRC declarations from the pinned ReactOS a97c8a2
dll/opengl/opengl32/icd.h (its field order and signatures are an ABI the loader
fixes); icd.h carries ReactOS's COPYING. The dispatch order is generated from that
header. The ICD's shipped renderer is the software reference rasterizer; no
hardware acceleration is claimed.

GFX11 shader generation, 2026-10-23 (src/opengl/gl_shader_gfx11.*, additive
graphics subset in src/hardware/gfx11_isa.* and tests/gfx11_interp.hpp): original
encoder and generator. New float VOP1/VOP2, EXP and s_sendmsg encodings are checked
byte-exact against the pinned LLVM 18.1.8 GFX11 MC vectors added under
work/upstream-gpuinit/llvm-mc-gfx11/ (gfx11_asm_exp.s, exp.s, exp-gfx10.s,
gfx11_asm_vinterp.s, gfx11_asm_ldsdir.s, gfx11_asm_mimg.s; Apache-2.0 WITH
LLVM-exception; SHA-256 in work/upstream-gpuinit/SHA256SUMS; test data only, not
shipped). The NGG vertex-shader allocation/parameter path and the user-SGPR layout
follow Mesa 24.2.0 (MIT) read as behaviour references and pinned under
work/upstream-gpuinit/mesa-24.2.0/ (ac_nir_lower_ngg.c, ac_nir.c, radv_shader_args.c,
ac_shader_args.h/.c, radv_pipeline_graphics.c, radv_shader_info.c, radv_shader.h,
aco_instruction_selection.cpp, aco_instruction_selection_setup.cpp, aco_interface.cpp,
ac_formats.c, ac_surface.c, ac_shader_util.h, si_shader.c/.h, si_state.c,
si_state_shaders.cpp; SHA-256 in SHA256SUMS); no Mesa code is copied or compiled in.
The generated shader datapath is verified only in the host interpreter; NGG geometry
wiring, context/surface register programming and hardware execution are unverified.

Adapted the real nonindexed draw tail and primitive/restart register writes,
shader program address split, register-space offsets and GFX11 NGG/PS bank
selection. GFX11 has no legacy vertex pipeline: vertex-only NGG uses the ES
program address registers and GS user-data bank. No compiled shader, Mesa shader
compiler, complete NGG/PS resource or render-target setup is copied or invented.

The GFX11 encoder reuses memory::Manager/Slice for trusted GPUVA bounds and read
permissions, sdma::CommandBuffer for bounded little-endian stores and the shared
test-only memory backing fixture. It does not bypass leases, expose a raw-packet
IOCTL, upload code or submit to hardware. Successful encoding proves packet
construction only. External compiled raw-pointer shader ABI, executable mappings,
program prefetch padding, full NGG/PS resources/GE subgroup setup/stage enables,
vertex uploads, color/depth descriptors, interpolation, raster/viewport/scissor,
cache barriers/chip workarounds, hardware GFX queue, fences and presentation are
all required before these packet primitives can participate in rendering.
