Adapted: legacy 8b/10b DPCD receiver fields, the 16-byte AUX payload limit,
bounded AUX DEFER retries, I2C-over-AUX EDID offset/segment transactions and
short-transfer rejection. The new C++ code reuses the existing strict EDID
decoder and mode budget instead of copying Linux runtime, packed structs or
kernel I2C/DRM services. A native DCN owner must still supply real bounded AUX,
HPD, PHY and source-capability callbacks. Downstream branches, 128b/132b
training and unverified RGB8 paths are refused; MST capability is recorded but
an SST backend must disable and verify MST mode. No link is trained or enabled.
src/output/dp_training.cpp now implements bounded 8b/10b SST clock recovery and
channel equalization over those callbacks, including source/sink pattern setup,
per-lane adjustment requests, RBR/HBR/HBR2 and HBR3 with verified TPS4
(scrambling left enabled for TPS4),
confirmed pattern disable and unknown-state
containment. No native Navi31 AUX/PHY callback is wired, so no physical link has
been trained by this project. LTTPR, DSC and multi-stream training
remain outside the supported policy.
Linux v6.12 dce_aux.c binds AUX to an owned DDC pin and a DC resource-engine
instance, then sequences AUX_SW_CONTROL/DATA, completion, reply and timeout
state. The new dp_port_native bridge requires that real routing and resource
ownership proof before using any callback. It does not substitute ATOM GPIO
indices for BAR5 offsets or issue these register writes without the matching
DCN3.2 AUX/HPD service:
https://github.com/torvalds/linux/blob/v6.12/drivers/gpu/drm/amd/display/dc/dce/dce_aux.c
src/output/dcn32_aux.cpp adapts that pinned software-engine arbitration,
bounded engine enable/reset, SW request/reply staging and completion/release sequence for five
DCN3.2 AUX register banks. Register indices and field masks come from
https://github.com/torvalds/linux/blob/v6.12/drivers/gpu/drm/amd/include/asic_reg/dcn/dcn_3_2_0_offset.h
https://github.com/torvalds/linux/blob/v6.12/drivers/gpu/drm/amd/include/asic_reg/dcn/dcn_3_2_0_sh_mask.h
The native adapter binds only under external exact DDC GPIO, AUX clock/PHY,
DMUB, HPD and register-epoch proof. It does not configure these prerequisites
or bind the physical miniport's connector; no mode is advertised. Uncertain
completion or arbitration release quarantines the engine. Copyright 2012-15

permissive notice reproduced for atom_connectors.cpp below also applies.

src/output/atom_connectors.cpp adapts BIOS parser2 ROM/master-data table lookup,
display object-info1.4/1.5 path traversal, skipping generic paths without an
encoder, I2C/HPD connector records and GPIO LUT matching. The checked parser
supports ROM2.2/master-data2.1, limits topology to 32 paths, validates complete
table extents, preserves 32-bit GPIO register indices instead of truncating
them, and rejects duplicate routing/ambiguous records, invalid GPIO shifts,
record cycles/nonprogress and paths/records escaping their owning tables.
Missing DDC/HPD/GPIO information stays explicitly unresolved. Connector object
IDs identify HDMI-A/DP/eDP/USB-C routing only; no monitor, trained link, register
address-space resolution or physical display initialization is invented.
No ATOM command interpreter, allocation, register write or firmware execution
is copied or performed by the parser.

Adapted: exact edid_header bytes, EDID modulo-256 block checksum validation,
drm_mode_detailed field extraction and 10-kHz clock scaling, minimum active
dimensions of 64, digital separate sync polarities, and
cea_for_each_detailed_block traversal bounded before the checksum byte.
CTA extended tag HF-EEODB=0x78 is detected and explicitly unsupported because
its block-count override has not been implemented. The EDID blob must exactly
match its base-declared length. No header repair, checksum forgiveness, EDID
quirks, silent sync clamping or partial corrupt-block acceptance are adapted.

https://raw.githubusercontent.com/torvalds/linux/v6.12/include/drm/drm_edid.h
SHA-256 be7f3d00c6e89583213f866c010ee41ef777f0cc6af32ca45758d81cefe88fb3
Adapted: detailed_pixel_timing byte positions and EDID digital depth encoding.
Physical bytes are decoded only through the project's checked ByteView rather
than Linux packed structs or native pointers. Stereo, borders, interlace and
composite sync are rejected. RGB8 requires independent verified link evidence;
unknown EDID depth does not establish RGB8 support.

DCN3.2 constructs separate link encoders, timing generators, DDC/AUX resources,
clock/bandwidth machinery and DMUB-related services. EDID parsing and an inert
AUX register adapter alone cannot initialize physical output. No firmware
operation or physical GPU access was performed during development.

Implementation scope: strict EDID 1.3/1.4 base blocks and CTA revisions 1..3,
at most eight complete blocks; at most 46 DTD candidates use the existing
64-mode catalog. A malformed/unsupported DTD is counted and omitted. Unknown
extensions are counted and not interpreted. Established/standard timings,
CTA short-video VICs, DisplayID, range inference, quirks, HDR, VRR, DSC, audio,
HDMI FRL, DP MST and physical transport/PHY integration are not implemented. A zero-mode
snapshot is valid discovery data and never a working output claim. The new DP
link policy can acquire EDID only through an owner-supplied AUX callback; the
native AUX register adapter is built but is not connected to a proven physical
connector/clock owner. It never enumerates connectors,
trains a link, performs a physical modeset or reports a physical display
operation successful. Its pure output validation
checks RGB8 pixel clock and a caller-verified usable payload budget, then returns
an existing display::Timing. ModeController/ModeBackend own scanout validation
and actual hardware commit. Missing capabilities fail explicitly.
